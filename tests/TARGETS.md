# Test targets

Generated by an `ast` walk of the source at b16ef6f: every module-level function, class and method, every
`argparse` option, and every YAML key, in
`bonsai/`, `backbone_based_bonsai/`, `bonsai_scout/`, `downstream_analyses/` and `optional_preprocessing/`.
`paper_figure_scripts_and_notebooks/` and `examples/` are out of scope. Tick `[x]` when a target has a test
(or write `n/a: <reason>` for dead or unreachable code), and keep the tick in the same commit as the test.

The "Test file" column follows the selection rule in tests/README.md: tests of `foo.py` live in a file named
exactly `test_foo.py`. "existing:" names a pre-existing test file (tests/test_*.py) that already imports the
target; those cover the numerics listed in TESTING.md, not necessarily every branch.

Changes from the proposed split, from the source:

- The SPR and NNI drivers (`do_spr_moveset`, `do_spr_moves_with_postprocessing`, `extensive_spr_postprocessing`,
  `nnnReorderRandom`, `nnnReorder`) and the tree methods of `SCData` (`compile_tree_from_mergers`,
  `communicate_tree_topology`, `find_branching_points`, `merge_clusters_acc_cellstates`, `set_node_edge_style`)
  live in `bonsai_dataprocessing.py` but are tree algorithms: area B, in `tests/area_b/test_bonsai_dataprocessing.py`.
  Area A writes `tests/area_a/test_bonsai_dataprocessing.py`; the two files never overlap.
- The tree utilities of `bonsai_helpers.py` (newick/hierarchy conversion, pair bookkeeping, `calcTInit`,
  `getAllDLogLs`, `OwnGraph`, `get_pdist_inds`) go to B; the rest of `bonsai_helpers.py` to A.
- YAML keys appear once, with two tick columns: A ticks that `create_config_file.py` writes the key and
  `Run_Configs` reads it back; C ticks the key's effect on a run.
- `downstream_analyses/get_clusters_max_diameter.py` is on the core path: `Tree.set_mindist_root` and
  `Tree.get_cluster_centers` call `get_min_pdists_clustering_from_nwk_str` in every `--step all`. Area D owns it;
  run its tests for every change to that file.
